## ODEStream日期及在线时序问题

原始date是被预测目标日；由原始股票交易日回退到前一个收盘信号日，并核验current_close/true_close。与主面板公共范围为2025-07-01—2026-06-04，225日、65,425键。原旧摘要66709是目标行回退日期、去掉7月1日目标后的行数，不是原CSV缺297行。

更关键：运行器只有一套共享model/optimizer，按目标日→股票排序，每条predict_one后立即update_one读取该条目标标签。同目标日除第一股外，后续股票已接受此前股票同目标日真实收盘监督。若要求在前一收盘时统一发布截面预测，该标签尚未可用；所以保存的ODEStream不能作为与HCA时序公平的确认性基线。此轮没有重新训练修复它，也不能通过回退日期修复权重已受监督的问题。证据见odestream_audit.json、逐日更新顺序CSV和原运行器。

## 不确定性及论文使用边界

paired_intervals_full_226.csv为配对日期块bootstrap：block10、5000次、seed20261013，重采样已实现日IC/收益，不重训练或重建持仓，未校正多重检验。收益较高不代表预测更准确或统计显著。

Chronos/TimesFM为本项目零样本，HCA包含历史监督训练与在线反馈，训练预算/输入协变量不同；不能把差异全部归于HCA结构。预训练版本对历史测试时点的可用性和预训练数据重叠未排除。固定当期成分股、未来完整窗口可评价样本筛选、已反复查看的单市场单窗口等限制保留。

新电脑先运行`git lfs pull`，再解压预测包。normalized_points/保留点预测十步收益与统一标签，run_metadata/保留原配置、版本、完成状态和数据指纹。sources.json和archive_manifest.json提供来源及字节哈希。

无需原始行情即可检查归档并重算：

```powershell
python scripts/evaluation/recheck_archived_baseline_points.py --model Chronos2 --verify-all-zips
python scripts/evaluation/recheck_archived_baseline_points.py --model TimesFM3
```

七个原始预测包已逐成员通过CRC与SHA256检查；从压缩归档重新读取Chronos点预测，主表收益、IC、RankIC、轨迹RMSE复算误差小于1e-12。原始源码计算与当前源CSV身份见`sources.json`；导出的点预测采用统一标签，而ZIP保留源CSV全部原始字段和精度。
