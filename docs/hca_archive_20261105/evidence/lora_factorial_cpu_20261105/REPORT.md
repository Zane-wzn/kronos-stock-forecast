# Kronos内部LoRA与排序目标：本机CPU小规模验证

日期：2026-11-05。结论：本配置没有通过初步有效性筛选，暂不扩大训练或上线。这里是负向的工程初筛，不是LoRA普遍无效的证明。

## 设置与预先规则

- 同一个公开Kronos-small权重与既有Prediction Adapter checkpoint；Kronos前6层和tokenizer冻结，后2层原权重冻结，仅Q/V注入rank4、alpha8 LoRA；当前Adapter/head可训练。LoRA增加16,384参数，总可训练88,650；无LoRA为72,266。
- A0：Adapter+原SmoothL1；A1：A0+内部LoRA；B0：Adapter+训练尺度标准化路径损失+0.1同日pairwise logistic排序损失；B1：B0+内部LoRA。B0/B1同时改变路径尺度与排序项，因此其差异不能进一步归因于单独排序项。
- 60股由训练元数据固定hash选择；4,583训练样本（80个历史日期）、2,368验证样本（40日期）、9,460测试样本（160连续交易日）；每样本90日输入、10日累计收益标签。每日期最多32股一个batch，3轮×80次更新；3种子100/200/300，四组同样的样本顺序和优化步。
- 训练2020-12-14—2024-12-13，验证2025-01-02—2025-06-13；训练标签末日早于验证首日，验证标签末日早于测试首日。
- LoRA LR1e-5、Adapter LR1e-5、head LR1e-4，AdamW无weight decay、clip1；eval关闭dropout，但LoRA与Adapter/head保留autograd。
- 验证规则：Path RankIC提高，且MAE/RMSE相对原checkpoint不恶化超过1%；否则回退epoch0。规则写入run_config，测试不参与选模。此次只有固定一套超参，未进行验证调参网格。
- 测试固定两段：2025-07-01—2025-10-28（80日/4787样本）；2025-10-29—2026-02-27（80日/4673样本）。第二段只是本轮额外时间块，项目此前可能查看过，不能称未触碰确认集。没有在线更新。

## 主要结果：未通过验证选择

原checkpoint验证Path RankIC为0.002086。表中“训练候选最好值”在三轮、三个种子中取最大，只用于展示候选范围，不是测试选择，也没有把它作为稳健效果。

|组|训练候选最好验证RankIC|选中epoch0的种子数|
|---|---:|---:|
|A0 原目标Adapter|−0.002761|3/3|
|A1 原目标LoRA+Adapter|−0.002700|3/3|
|B0 标准化+排序目标Adapter|−0.003437|3/3|
|B1 标准化+排序目标LoRA+Adapter|−0.003469|3/3|

所有训练候选的验证RankIC都低于原模型。数值误差有改善，例如训练候选的验证MAE最低约0.030505，而原模型为0.031161；但预设主目标是排序，不能用MAE改善替代RankIC。12个候选均回退原checkpoint。

因此测试部署指标全部相同，不能把这些原模型回退收益当成LoRA收益，也不能声称训练后的模型完全等价。选中LoRA矩阵仍为零输出初始化，没有部署其训练更新。

## 正确性、缓存和耗时

- 实际最终运行1635秒（约27.25分钟）；16,411条序列冻结前缀缓存生成约394.7秒（6.58分钟）。不是原先估计的数天：此次只取小面板，并缓存前6层，只对末2层反传。
- LoRA组每组三轮实际反传并验证约137—147秒，另有测试推理；普通头组训练约1秒，参数量少并不等价于端到端耗时相同。
- 重新提取前6层输出prefix，不用已损坏的旧hidden_train.npy；相同keys最终hidden与前次缓存差异检查记录于cache_manifest。
- tokenizer与原骨干在特征生成前后参数hash一致；12组各自冻结参数训练前后hash一致。第2次更新LoRA A/B梯度均非零、有限，证据在audit.json。真实Transformer后缀初始化输出相等、训练后原权重不变的单元测试通过。
- 实验代码与模块10项相关测试通过。所有组在预测相同输入时初始化误差容差1e-6，float32缓存。
- 最终相同预测来自fallback，而非漏配优化器；LoRA确实训练，验证却不接纳。原冻结权重训练期间不更新。

## 判断与边界

初步判定：当前rank4/末2层/学习率与240更新步、60股历史抽样配置，没有值得部署的排序增益。不能说LoRA方法普遍无效：仅一个稀疏历史训练样本面板、单验证期、一套LR/秩/排序权重，训练目标还同时改变尺度；未覆盖更充分训练、其他市场与不同标签。

保留原模型，不为测试收益解除验证门，也不事后挑训练轮。若继续，先在合法历史验证期诊断“误差改善但排序退化”及梯度尺度，分别控制head/adapter更新幅度、路径标准化、排序项；再决定是否值得做较大验证。暂不直接增加LoRA专家或层数。

- training_history.csv：每组/种子/轮验证MAE、RMSE、RankIC及loss。
- selection.csv：12个epoch0回退记录。
- metrics.csv：全部组/种子/两个时间块/Path和Endpoint指标。
- evaluation/*/summary.json：逐期限误差、方向F1/MCC、OOS R²、ICIR/日期块区间、分位和组合等详细指标。
- audit.json：冻结参数hash和LoRA梯度。
- cache_manifest.json/source_manifest.json：权重、数据与源码身份。
