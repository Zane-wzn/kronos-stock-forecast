汇报主线：从历史行情构造时间序列样本，用预训练模型形成表示或预测，再通过 Adapter、排序头和持续更新适应市场变化，并在统一时间边界下评估。

1. 项目在解决什么问题

3. 数据怎么变成训练样本

CSI300 对齐主实验采用按时间切分的股票日期面板。每条样本对应一只股票在一个预测日的输入与未来标签。主口径使用 90 个真实交易日作为历史窗口，预测后续 10 个交易日。

字段/概念通俗解释作用
as_of_date做出预测的日期决定模型当时可以使用哪些信息。
输入窗口预测日前 90 个交易日描述股票近期的历史走势。
label_start_date / label_end_date未来 10 日标签的开始与结束判断标签是否已经完全揭晓。
目标收益未来各日相对当前收盘价的收益训练回归头或计算排序目标。
hiddenKronos 对输入窗口形成的 512 维表示供 Adapter 或预测头继续学习。
rh = Ph / P0 − 1；样本路径信号 = (r1 + … + r10) / 10；终点信号 = r10
时间边界：模型在预测日只能看过去。未来标签只有到 label_end_date 后才成熟；持续更新必须满足 as_of_date < update_date 且 label_end_date <= update_date，否则会泄漏未来信息。

4. 模型对照与 Adapter 结构

Zero-shot

直接调用预训练模型预测，不使用本项目训练出来的预测头。Chronos-2 和 TimesFM 3.0 的 CPU 实验属于独立零样本基线。

Linear / Ranking Head

在 Kronos 缓存特征上训练较小的预测头。线性头主要拟合数值；排序头重点学习同一天股票之间的相对顺序。

Prediction Adapter

在隐藏特征上增加小型可训练模块，改变表示后输出预测路径。Backbone 隐藏特征缓存固定，不在这套持续实验里反向更新 Kronos。

Continual ABC

A 是原始信号对照，B 是测试前训练后冻结的排序头，C 是测试期间按计划持续更新的头。持续更新主体是 C。

Adapter 的前向计算

h (512维)
  → LayerNorm
  → Linear(512 → 64)
  → GELU
  → Dropout(p=0.1)
  → Linear(64 → 512)
  → 与输入 h 残差相加
  → Linear(512 → 10)，输出未来10步
z = γ ⊙ (h − μ) / √(σ² + ε) + β
Adapter(h) = h + Wup Dropout(GELU(Wdown z + bdown)) + bup
ŷ = Whead Adapter(h) + bhead

LayerNorm 的 γ、β 和两层 Linear 的权重、偏置是可训练参数；GELU、Dropout、残差连接本身没有训练参数。Adapter 的上投影初始化为零，使开始时 Adapter 分支对表示的改动为零。

训练目标

L = LSmoothL1(ŷ, y) + λrank Lpairwise-rank，当前 λrank 默认 0.2

Smooth L1 让预测收益数值接近真实收益；pairwise 排序损失鼓励真实收益较高的股票获得更高预测分数。训练使用 AdamW、梯度裁剪，并在验证集上保留本轮表现最好的 epoch。

5. 持续学习：什么时候更新、拿什么更新

持续学习不是每天拿当天结果训练，而是在新标签真正成熟后，定期把新信息加入训练，让模型尝试适应变化，同时用历史数据降低遗忘。

更新概念本项目做法为什么这样做
更新节奏测试期每月最后一个交易日更新模拟定期模型维护，而不是每天剧烈调整。
Test-then-train更新日先预测，再训练；新模型下一交易日生效保证当天预测没有使用当天之后的信息。
成熟标签预测日期早于更新日，且标签结束日不晚于更新日确保目标收益在更新时确实已知。
Replay 回放最多 120,000 条；目标为近期 24 个月约 70%，较早历史约 30%，历史部分按年份分层抽样兼顾近期适应性与旧规律，减少灾难性遗忘。
Warm start从当前模型复制出候选模型继续训练保留已有知识；失败候选可丢弃。
模型验收候选在固定验证集通过对应门控后才替换当前模型避免只因训练集损失变好就上线。

5.1 什么时候触发更新：月末日历条件

代码先把测试集中的交易日按先后排列为 d1, …, dT。如果某个日期之后的下一个测试交易日已经进入新月份，就把当前日期定为更新日：

U = { di : month(di) ≠ month(di+1) }，i = 1, …, T−1

因此“月末”指该测试交易日序列中的最后一个交易日，不是固定的每月 30 日或 31 日。测试区间最后一天若后面没有下一个测试日期，代码不会仅凭它是区间终点额外触发一次更新。

日期例子：假设 8 月最后一个测试交易日是 8 月 29 日，下一测试交易日是 9 月 1 日。模型先用当前版本预测 8 月 29 日；预测完成后才检查成熟标签并尝试更新；如果候选通过门控，从 9 月 1 日开始使用新版本。

5.2 哪些新数据可以用：标签成熟条件

令样本 j 的预测日为 aj、未来标签结束日为 ej，更新日为 u。该样本可以进入更新数据的必要条件是：

M(u) = { j : aj < u 且 ej ≤ u }

新成熟数据是这次更新相较上次新增的成熟样本：N(u) = M(u) \ Mseen。若 N(u) 为空，脚本跳过本次训练。这个判定同时排除“预测日期在更新日或之后”的样本，以及未来 10 日标签尚未结束的样本。

5.3 回放集怎样组成

每次更新都从可用的训练历史和已经成熟的测试样本组成池子，再按标签结束日划分近期与较早历史：

P(u) = Ptrain ∪ M(u)，且所有样本满足 ej ≤ u
近期 R(u) = { j ∈ P(u) : ej ≥ u − 24 个月 }
目标配额：nrecent ≈ 0.70K，nhistory ≈ 0.30K，K = min(120,000, |P(u)|)

近期样本随机抽取；历史样本按标签结束年份分层抽取。70/30 是目标比例：如果某一侧可用样本不足，空出的名额会优先补给另一侧，所以实际比例可能不同。

5.4 从当前模型训练候选模型

把当前参数记为 θt。候选模型从 θt 的副本开始，在回放集上训练 Adapter 与预测头：

θcand(0) = θt；　L = LSmoothL1(ŷ, y) + 0.2 Lrank

每个 epoch 后在固定验证集计算验证指标，并保留本轮训练中指标最好的参数，而不是无条件采用最后一个 epoch。Adapter 默认每次更新最多训练 2 个 epoch；早停耐心值为 2。可把优化过程概括为：

θcand = arg maxθ ∈ checkpoints(训练过程) RankICval(θ)

5.5 门控公式：候选模型何时接替当前模型

Adapter 持续学习：若候选验证 RankIC 有限且不低于当前 Champion，就接受候选；否则拒绝。

接受 Adapter 候选 ⇔ finite(RankICcand) 且 RankICcand ≥ RankICchampion

Continual ABC 的 MAE 门控版本：当前严格版本要求候选验证 MAE 有限且不高于 Champion；默认容忍度为 0。

接受 ABC 候选 ⇔ finite(MAEcand) 且 MAEcand ≤ MAEchampion

通过后才更新模型版本、保存 checkpoint，并把候选设为新的 Champion；失败时当前模型参数和版本保持不变。RankIC 与 MAE 是不同目标：前者考察股票排序，后者考察数值误差，所以两种门控不能混成一个结论。

本项目的 Adapter 结果状态：Adapter 门控依赖验证 RankIC。该计算曾存在预测展平和行序对齐问题，相关 CSI300/CSI800 运行脚本现已修复；旧实验的 epoch 选择与更新接受记录应由修复后的完整重跑重新产生。
形象理解：当前线上模型是“冠军模型”，更新出来的是“挑战者”。挑战者在同一套验证题上至少达到规定标准，才接替冠军；否则继续使用原模型。

6. 如何判断预测或更新有没有帮助

指标回答的问题解读方向
MAE / Smooth L1预测数值离真实收益有多远？通常越低越好。
IC预测分数与真实收益的线性相关程度如何？通常越高越好。
RankIC预测的股票排序与真实排序是否一致？越高表示横截面排序越一致。
Q5−Q1预测最高组的真实收益是否高于最低组？反映简单分组区分能力，不等于扣成本后的收益。
组合回测按指定持仓与交易规则后，收益、回撤和成本如何？必须结合交易成本、换手和回撤解读。

数值预测更准不必然代表排序更好；排序更好也不必然代表扣除交易成本后盈利。汇报时应把预测指标与策略回测分开陈述。

ABC 实验存在 MAE 门控变体；Adapter 持续脚本的设计门控是验证集 RankIC。具体结果必须以对应运行的 run_config.json、update_log.csv 和模型代码为准。

7. 当前审计结论与实验状态

Adapter RankIC 修复：CSI300 与 CSI800 Adapter 持续运行脚本原先把 (N,10) 预测直接展平，却将标签压成每样本一个 10 日均值；验证预测还按日期批次拼接，可能与元数据原始行序错位。现在脚本改为每行保留原样本位置，并用每条样本的 10 步均值计算横截面 RankIC，同时对形状和索引做检查。

修复涉及：

  • scripts/experiments/run_adapter_continual_csi300_90x10.py
  • scripts/experiments/run_adapter_continual_csi800_90x10.py
  • 回归测试：tests/test_adapter_rankic.py

两份脚本与测试通过 Python 语法编译检查；当前 CPU Python 环境缺少 NumPy、pandas、PyTorch，新增数值测试尚未执行。Adapter 旧实验用验证 RankIC 选择 epoch 和接受更新，因此旧版本选择与接受记录应视为待复核；要得到可信的新持续学习结果，应从初始 checkpoint 完整重跑 Adapter，并重算其下游预测评估。

ABC 使用每只股票一个标量预测分数，其 RankIC 路径与 Adapter 的 10 步向量输出不同；本次审计没有发现同样的展平形状问题，代码已做静态核查，但这不等于全量端到端重跑验证。

运行环境建议：本机 i7-10700 有 8 核、16 线程，但当前 Python 环境没有运行依赖。曾有 Adapter GPU 运行记录约 354 秒；不能据此可靠换算 CPU 用时。完整重跑优先使用原远程 GPU 实验环境，且使用新的输出目录保留旧结果作对照。

8. 向导师汇报时可按这条主线讲

  1. 研究问题：检验预训练时间序列表示能否帮助 A 股未来收益预测，并研究市场变化下轻量模型的持续适应。
  2. 数据协议：按股票与日期构造历史 90 日、未来 10 日样本，严格按时间切分，并用标签结束日约束可用信息。
  3. 方法对照：从原始预训练模型零样本，到线性头、Adapter、排序头；再对比测试期冻结与持续更新。
  4. 持续机制：月末先预测，等待标签成熟，将近期和分层历史样本回放训练候选模型，通过固定验证门控后让新版本从下一交易日生效。
  5. 评价维度：用误差衡量数值预测，用 RankIC 衡量股票排序，用包含成本的回测检验策略结果。
  6. 当前可信度：Adapter 的 RankIC 门控实现已修复，但需要重跑后才能更新关于 Adapter 持续学习有效性的实验结论；将 ABC 结果与 Adapter 结果分开说明。
